# vk-study-bot

## О проекте

Это учебный VK-бот для поэтапного изучения материалов: книг, конспектов лекций и других текстов. Бот принимает на вход учебный материал, разделяет его на блоки-уроки и помогает пользователю изучать их постепенно, проверяя усвоение после каждого блока.

На каждом этапе пользователь читает блок материала и отвечает на проверочные вопросы. Бот оценивает ответы и корректирует дальнейший план: если материал усвоен плохо — возвращает к повторению, если хорошо — двигается дальше. Расписание занятий настраивается индивидуально.

Позже бот будет поддерживать несколько пользователей с общими материалами, поэтому учебные тексты хранятся отдельно от профилей пользователей и связываются через базу данных.

## Составные части проекта

- **VK API клиент** (`vk/VkApiClient`) — обёртка над VK API: отправка сообщений, получение long-poll сервера. Инкапсулирует HTTP-запросы и парсинг JSON.
- **Бот** (`bot/VkBot`) — главный цикл приёма событий через Long Poll, маршрутизация сообщений в команды. Устойчив к сетевым сбоям: при ошибке логирует и переподключается.
- **Система команд** (`commands/`) — интерфейс `Command`, реестр `CommandRegistry`, реализации `AuthorCommand`, `AboutCommand`, `HelpCommand`. Новая команда автоматически попадает в `/help` — ручная правка не нужна.
- **База данных (в планах)** — PostgreSQL, таблицы `users`, `books`, `lessons`. Хранение учебных материалов отдельно от прогресса пользователей.
- **Тесты** (`src/test/`) — функциональные тесты на JUnit 5: проверка команд, реестра и обработки сообщений.

## Алгоритмы обработки учебных материалов

### 1. Разбиение текста на блоки

Текст проходит три этапа обработки: структурный анализ → смысловое разбиение → нормализация блоков.

```
┌──────────────────┐      ┌──────────────────┐     ┌──────────────────┐
│  Структурный     │────▶│  Смысловое       │────▶│  Нормализация    │
│  анализ          │      │  разбиение       │     │  блоков          │
└──────────────────┘      └──────────────────┘     └──────────────────┘
```

#### Этап 1. Структурный анализ

Цель — найти «опорные точки» текста, по которым можно определить границы разделов.

**Для PDF-документов** (учебники, книги):
- Чтение метаданных PDF: размер шрифта, начертание (bold/italic) для каждого абзаца.
- Абзацы с крупным или жирным шрифтом помечаются как заголовки.
- Определяется иерархия: H1 (крупнейший) → H2 → H3.

**Для текстовых файлов** (конспекты, .txt, .md):
- Поиск заголовков по ключевым словам и паттернам регулярных выражений:

```text
^(Глава|Тема|Раздел|Параграф|§\d+|Пункт)\s*[\d.]*\s*.+
```

- Поиск markdown-заголовков (`#`, `##`, `###`).
- Поиск строк, состоящих только из цифр и точки (нумерованные разделы).

**Результат этапа:** список «маркеров раздела» с позицией в тексте и уровнем иерархии.

#### Этап 2. Смысловое разбиение

Если структурные маркеры найдены — текст делится по ним.

Если маркеры не найдены или их мало (неструктурированный конспект) — включается fallback:

1. Текст разбивается на абзацы (по пустым строкам).
2. Для каждой пары соседних абзацев вычисляется **косинусная близость** векторов TF-IDF.
3. Резкие падения сходства (ниже порогового значения) отмечаются как границы блоков.
4. Блоки, получившиеся короче 200 слов или длиннее 1500 слов, объединяются/дробятся для соблюдения целевого размера (500–800 слов на блок).

```
Сходство
  1.0 │ ████  ████      ████
      │   ████  ████ ████  ████
  0.5 │                     ████
      │                          ████  ← граница блока
  0.2 │
      └──────────────────────────────▶ абзацы
```

**Принцип перекрытия:** соседние блоки имеют небольшое перекрытие (1–2 предложения из конца предыдущего блока попадают в начало следующего), чтобы не разрывать связность изложения.

#### Этап 3. Нормализация блоков

- Очистка от лишних пробелов, переносов строк, мусорных символов.
- Если блок слишком длинный — деление по предложениям с сохранением контекста.
- Каждому блоку присваивается: порядковый номер, заголовок (если найден), диапазон исходного текста.

---

### 2. Формирование тестов для блоков

Для каждого блока генерируется набор вопросов. Поддерживаются три типа вопросов:

| Тип | Формат | Пример |
|-----|--------|--------|
| Выбор ответа | 1 правильный + 3 дистрактора | «Что такое инкапсуляция?» — 4 варианта |
| Верно/неверно | Утверждение + да/нет | «Инкапсуляция скрывает реализацию» — верно/неверно |
| Краткий ответ | Открытый вопрос | «Назовите принцип ООП, связанный с сокрытием» |

#### Алгоритм генерации вопросов

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐     ┌──────────────┐
│  Извлечение  │──▶│  Отбор        │──▶│  Формирование│───▶│  Генерация   │
│  ключевых    │    │  опорных     │    │  вопросов по │     │  дистракторов│
│  слов        │    │  предложений │    │  шаблонам    │     │              │
└──────────────┘    └──────────────┘    └──────────────┘     └──────────────┘
```

**Шаг 1. Извлечение ключевых слов**
- TF-IDF по корпусу всех блоков одного материала — слова с наибольшим весом в блоке.
- Фильтрация стоп-слов (предлоги, союзы, местоимения).
- Результат: 5–10 ключевых слов на блок.

**Шаг 2. Отбор опорных предложений**
- Предложения, содержащие 2 и более ключевых слова — кандидаты на основу вопроса.
- Предложения с маркерами определений («называется», «представляет собой», «— это») — приоритетные кандидаты.
- Предложения с перечислениями («во-первых», «с одной стороны») — для вопросов на соответствие.

**Шаг 3. Формирование вопросов по шаблонам**
- Шаблонные трансформации утвердительных предложений в вопросительные:

| Исходное предложение | Тип вопроса | Результат |
|----------------------|-------------|-----------|
| «Инкапсуляция — это сокрытие деталей реализации» | Выбор ответа | «Что такое инкапсуляция?» + 4 варианта |
| «Полиморфизм позволяет переопределять методы» | Верно/неверно | «Полиморфизм позволяет переопределять методы. Верно?» |
| «Наследование передаёт свойства родителя потомку» | Краткий ответ | «Какой механизм передаёт свойства родителя потомку?» |

**Шаг 4. Генерация дистракторов** (неправильных, но правдоподобных ответов)
- Из ключевых слов других блоков того же материала (тематически близкие, но неверные).
- Из предопределённого набора «похожих» терминов (если материал по ООП — дистракторы из терминологии ООП, не из случайных слов).
- Дистракторы не должны быть очевидно неверными.

#### Хранение тестов

Каждый тест сохраняется в БД и связан с конкретным блоком. Вопросы генерируются один раз при загрузке материала, а не при каждом тестировании пользователя. Это позволяет переиспользовать тесты для разных пользователей с одним и тем же материалом.

---

### 3. Оценка результатов теста

#### Модель оценки

Каждый ответ пользователя оценивается в баллах:

| Тип вопроса | Максимальный балл | Проверка |
|-------------|-----------------|----------|
| Выбор ответа | 1 | Точное совпадение с правильным вариантом |
| Верно/неверно | 1 | Точное совпадение |
| Краткий ответ | 2 | Нечёткое сравнение: ключевые слова ответа vs ключевые слова эталона |

**Для кратких ответов** используется сравнение по множеству ключевых слов:
- 2 балла — все ключевые слова эталона присутствуют в ответе.
- 1 балл — присутствует не менее 50% ключевых слов.
- 0 баллов — менее 50% ключевых слов.

#### Расчёт итоговой оценки блока

```
score_блока = (сумма баллов по всем вопросам) / (максимально возможная сумма баллов) × 100%
```

#### Пороговые значения и последствия

| Оценка | Действие бота |
|--------|---------------|
| ≥ 80% | Блок засчитан. Переход к следующему блоку. Интервал повторения увеличивается. |
| 60–79% | Блок засчитан условно. Бот отправляет пояснения по вопросам с ошибками. Переход к следующему блоку, но интервал повторения сокращается. |
| < 60% | Блок не засчитан. Бот предлагает перечитать материал и пройти тест заново через заданное пользователем время. |

#### Адаптация расписания (spaced repetition)

Бот использует модифицированный алгоритм SM-2:

1. Каждый блок имеет **интервал повторения** (в днях) и **фактор лёгкости** (начальное значение 2.5).
2. После каждого теста:
   - Оценка ≥ 80%: `интервал *= фактор_лёгкости`, `фактор_лёгкости += 0.1`
   - Оценка 60–79%: `интервал` без изменений, `фактор_лёгкости -= 0.2`
   - Оценка < 60%: `интервал = 1 день`, `фактор_лёгкости -= 0.5`
3. Фактор лёгкости не опускается ниже 1.3.
4. Если пользователь настроил расписание (например, «учиться по будням»), интервал корректируется: повторение переносится на ближайший разрешённый день.

```
Пример для блока №3:

День 1: изучение → тест (85%) → следующий повтор через 3 дня
День 4: повторение → тест (70%) → следующий повтор через 3 дня (интервал не вырос)
День 7: повторение → тест (50%) → следующий повтор через 1 день
День 8: повторение → тест (90%) → следующий повтор через 7 дней
```

#### Хранение прогресса

Прогресс пользователя по каждому блоку хранится в БД и включает:
- Текущий статус (не начат / изучается / повторяется / завершён).
- Количество попыток прохождения теста.
- Последнюю оценку.
- Текущий интервал повторения и фактор лёгкости.
- Дату следующего запланированного повторения.
